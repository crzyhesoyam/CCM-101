# Reflection

Of all the cloud infrastructure components covered in this lab, I believe compute resources are the most important. Storage and networking are essential too, but without compute, there's nothing to actually execute a workload — every other component exists to support it. That said, all four components work together, and a real cloud system can't function properly if any one of them is missing or misconfigured.

Linux plays a major role in supporting cloud computing because it's lightweight, open-source, and highly customizable. Since it doesn't require licensing fees and can run efficiently on minimal resources, cloud providers can deploy it at scale without high overhead costs. Its strong command-line tools also make server management easier to automate, which matters when a provider is managing hundreds or thousands of cloud instances at once.

Technical documentation is important before deploying infrastructure because it ensures everyone on a team understands what's being built, why, and how it's configured. Good documentation helps catch mistakes early, gives senior engineers the context they need to review a plan, and makes future troubleshooting or scaling much easier since no one has to reverse-engineer past decisions.

Through this lab, I learned how to use basic Linux commands to inspect a server's hardware, storage, and network configuration. I also practiced comparing equivalent services across AWS, Azure, and GCP, and became more comfortable writing structured technical documentation in Markdown, including tables and organized headings.

Completing this mission has improved my GitHub portfolio by adding an organized project that goes beyond just code, it now includes clear documentation, a diagram, and evidence of hands-on server investigation. This makes it easier to show potential employers or collaborators that I can work with cloud infrastructure and communicate technical findings clearly, not just write scripts.
